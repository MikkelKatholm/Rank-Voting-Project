## sbits and sint
### What do we do
We send ballots one number at a time from the client to the server as a `sint` and then on the server we receive a flattened list `list[sint]` 
### Why
The client interface only supports the types `sint` and `sfix` that is why we used `sint`.
To format as a ballot we will later just format the flattened list as a `Matrix`

### Problems
As our prior solution for the tallying process use `sbit` we tried to cast the ballot to `sbit` instead of `sint` using the below setup.
```python
SEC_PARAM = int(os.getenv("SEC_PARAM"))
NBITS = max(SEC_PARAM, (NUM_VOTES + 1).bit_length())
sb = sbits.get_type(NBITS)
siv = sbitintvec.get_type(NBITS)
```
This blows absolutely everything up and the programs halts.
We think we are going to change the tallying to use `sint` instead of `sbit` though it might slow down the tallying.
